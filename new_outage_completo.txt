# 🚨 Auto Outage GMUD Observabilidade

> **Objetivo:** automatizar a criação de **Maintenance Windows no Dynatrace** e **Maintenances no Zabbix** a partir de GMUDs aprovadas para o time de Observabilidade, eliminando atividades manuais e aumentando a rastreabilidade operacional.

https://img.shields.io/badge/status-ativo-brightgreen
https://img.shields.io/badge/automation-AAP-red
https://img.shields.io/badge/monitoring-Dynatrace-orange
https://img.shields.io/badge/monitoring-Zabbix-red
https://img.shields.io/badge/ITSM-Jira-blue

---

# 🧭 Em poucas palavras

O projeto identifica automaticamente GMUDs que possuem atividades de aprovação para o grupo:

```text
OBSERVABILIDADE(APR)
```

A partir dessas GMUDs, a automação:

✅ Descobre os ativos vinculados na CMDB

✅ Localiza os servidores relacionados

✅ Busca os respectivos HOSTs e SERVICEs no Dynatrace

✅ Cria uma única Maintenance Window contendo todos os componentes encontrados

✅ Cria a Maintenance correspondente no Zabbix

✅ Gera uma planilha detalhada com todos os ativos processados

✅ Envia relatório por e-mail

---

# 🔄 Fluxo simplificado

```text
Jira GMUD

```

# 📋 O que a automação faz

## 1️⃣ Descobre GMUDs elegíveis

A automação consulta o Jira procurando atividades com status:

```text
Aguardando aprovação dos Executantes
```

e executante:

```text
OBSERVABILIDADE(APR)
```

A partir dessas atividades, identifica automaticamente a GMUD pai relacionada.

---

## 2️⃣ Obtém os ativos da CMDB

Cada GMUD possui um campo:

```text
customfield_14007
```

que referencia objetos do Jira Assets.

A automação suporta:

### ✅ Um ativo

Exemplo:

```text
P00PP4
```

### ✅ Vários ativos

Exemplo:

```text
PS8
FachadaSOACRM
```

### ✅ Objeto do tipo Sistema

```text
Sistema
 ├─ srv01
 ├─ srv02
 └─ srv03
```

### ✅ Objeto do tipo Servidor

```text
NET002PRDSAS025
```

---

## 3️⃣ Busca os ativos no Dynatrace

Após expandir a CMDB, a automação procura:

### HOSTs

Utilizando os nomes dos servidores.

Exemplo:

```text
NET002PRDLNX395
BRUX0206
ECC05CASDB02
```

---

### SERVICEs

Utilizando o nome do sistema CMDB.

Exemplo:

```text
GITLAB
P00PP4
MPE
```

---

## 4️⃣ Cria uma única Maintenance Window

Todos os componentes encontrados são consolidados.

Exemplo:

```text
HOST-123
HOST-456
SERVICE-ABC
SERVICE-DEF
```

Resultado:

```text
1 GMUD
1 Maintenance Window
N HOSTs
N SERVICEs
```

---

## 5️⃣ Cria Maintenance no Zabbix

Quando habilitado:

```yaml
zabbix_habilitado: true
```

a automação também cria a manutenção correspondente no Zabbix.

A busca dos hosts é case-insensitive através de consultas em:

```text
UPPER
LOWER
```

para aumentar a taxa de sucesso.

# 🧪 Modo de teste

Para validar a automação sem criar uma Maintenance Window real:

```yaml
dynatrace_validate_only: true
```

Nesse modo:

✅ Busca ativos

✅ Busca HOSTs

✅ Busca SERVICEs

✅ Valida payload

✅ Gera relatório

❌ Não cria Maintenance Window

---

# 🧪 Teste sem GMUD real

Caso não existam GMUDs abertas, é possível utilizar uma GMUD fictícia.

Arquivo:

```text
roles/outage/vars/main.yml
```

Exemplo:

```yaml
gmuds:
  - chave: "GML-TESTE"
    resumo: "Teste Dynatrace"
    inicio: "2026-09-18T18:08:00.000-0300"
    fim: "2026-09-18T19:10:00.000-0300"
    ativos:
      - "901269"
```

Para esse cenário basta comentar a role:

```yaml
# - role: descoberta
```

no playbook principal.

- Produzir rastreabilidade operacional

---
# ============================================================
# 1. Buscar atividades que estão aguardando aprovação
# ============================================================

- name: Buscar atividades de Observabilidade
  ansible.builtin.uri:
    url: "{{ jira_base_url }}/rest/api/3/search/jql"
    method: POST
    force_basic_auth: true
    user: "{{ jira_user }}"
    password: "{{ jira_password }}"
    headers:
      Accept: application/json
      Content-Type: application/json
    body_format: json
    body:
      jql: >-
        project = {{ projeto_jira }}
        AND (
          status = "Pronto para Implementação"
          OR status = "Atividade em execução"
        )
      maxResults: 1000
      fields:
        - summary
        - customfield_14998
        - issuelinks
    status_code: 200
  register: jira_search
  environment: "{{ proxy_env }}"
  no_log: false


# ============================================================
# 2. Filtrar somente as atividades de Observabilidade
# ============================================================

- name: Selecionar somente atividades de Observabilidade
  ansible.builtin.set_fact:
    atividades_observabilidade: >-
      {{
        jira_search.json.issues | default([])
        | selectattr('fields.customfield_14998', 'defined')
        | selectattr('fields.customfield_14998.value', 'defined')
        | selectattr(
            'fields.customfield_14998.value',
            'equalto',
            executante_alvo
          )
        | list
      }}


# ============================================================
# 3. Descobrir as GMUDs pai
# ============================================================

- name: Identificar as GMUDs pai
  ansible.builtin.set_fact:
    gmuds_pai: >-
      {{
        atividades_observabilidade
        | map(attribute='fields.issuelinks')
        | flatten
        | selectattr('inwardIssue', 'defined')
        | map(attribute='inwardIssue.key')
        | unique
        | list
      }}


# ============================================================
# 4. Buscar os dados completos de cada GMUD
# ============================================================

- name: Consultar dados completos das GMUDs
  ansible.builtin.uri:
    url: "{{ jira_base_url }}/rest/api/3/issue/{{ item }}?fields=*all"
    method: GET
    force_basic_auth: true
    user: "{{ jira_user }}"
    password: "{{ jira_password }}"
    headers:
      Accept: application/json
    status_code: 200
  loop: "{{ gmuds_pai }}"
  register: gmuds_jira
  environment: "{{ proxy_env }}"
  no_log: false
  loop_control:
    label: "{{ item }}"


- name: Debug quantidade de ativos CMDB
  ansible.builtin.debug:
    msg:
      gmud: "{{ item.json.key }}"
      quantidade: "{{ item.json.fields.customfield_14007 | length }}"
      ativos: "{{ item.json.fields.customfield_14007 }}"
  loop: "{{ gmuds_jira.results }}"
  loop_control:
    label: "{{ item.json.key }}"
# ============================================================
# 5. Inicializar resultado
# ============================================================

- name: Inicializar lista de GMUDs
  ansible.builtin.set_fact:
    gmuds: []


# ============================================================
# 6. Extrair informações das GMUDs
#
# O campo customfield_16348 é ADF.
#
# Estrutura observada:
#
# content
#   └── paragraph
#         └── content
#               ├── "Ativos Afetados:"
#               └── " brwin0291"
#
# Primeiro montamos o texto de cada parágrafo.
# ============================================================

- name: Processar cada GMUD
  ansible.builtin.set_fact:
    gmuds: >-
      {{
        gmuds + [
          {
            'chave': item.json.key,
            'resumo': item.json.fields.summary,
            'inicio': item.json.fields[jira_inicio_field],
            'fim': item.json.fields[jira_fim_field],
            'ativos': (
              item.json.fields.customfield_14007
              | default([])
              | map(attribute='objectId')
              | list
            )
          }
        ]
      }}
  loop: "{{ gmuds_jira.results }}"


# ============================================================
# 7. Validar resultado
# ============================================================

- name: Validar informações das GMUDs
  ansible.builtin.assert:
    that:
      - item.inicio is defined
      - item.inicio is not none
      - item.fim is defined

# Recebe a variável "gmud" (loop_var definido em main.yml).
# Só é incluída quando zabbix_habilitado for true (ver main.yml).

- name: Converter janela da GMUD para o formato do Zabbix
  ansible.builtin.set_fact:
    zbx_inicio: >-
      {{ (gmud.inicio | to_datetime('%Y-%m-%dT%H:%M:%S.%f%z')).strftime('%Y-%m-%d %H:%M') }}
    zbx_fim: >-
      {{ (gmud.fim | to_datetime('%Y-%m-%dT%H:%M:%S.%f%z')).strftime('%Y-%m-%d %H:%M') }}
    zbx_minutos: >-
      {{ ((
            (gmud.fim   | to_datetime('%Y-%m-%dT%H:%M:%S.%f%z'))
          - (gmud.inicio | to_datetime('%Y-%m-%dT%H:%M:%S.%f%z'))
         ).total_seconds() / 60) | round | int }}

- name: Validar duração da janela
  ansible.builtin.assert:
    that:
      - zbx_minutos | int > 0
    fail_msg: >-
      GMUD {{ gmud.chave }}: janela inválida
      ({{ gmud.inicio }} -> {{ gmud.fim }}).

- name: Localizar ativos no Zabbix (UPPER)
  community.zabbix.zabbix_host_info:
    host_name: "{{ item | upper }}"
    exact_match: true
  loop: "{{ gmud.ativos }}"
  delegate_to: "{{ zabbix_inventory_host }}"
  register: zbx_busca_upper
  failed_when: false

- name: Localizar ativos no Zabbix (LOWER)
  community.zabbix.zabbix_host_info:
    host_name: "{{ item | lower }}"
    exact_match: true
  loop: "{{ gmud.ativos }}"
  delegate_to: "{{ zabbix_inventory_host }}"
  register: zbx_busca_lower
  failed_when: false

- name: Montar lista de hosts encontrados
  ansible.builtin.set_fact:
    zbx_hosts: >-
      {{
        (
          (
            zbx_busca_upper.results
            +
            zbx_busca_lower.results
          )
          | selectattr('hosts', 'defined')
          | map(attribute='hosts')
          | flatten
          | map(attribute='host')
          | unique
          | list
        )
      }}

- name: Definir se a GMUD é válida para o Zabbix
  ansible.builtin.set_fact:
    gmud_valida_zabbix: "{{ zbx_hosts | length == gmud.ativos | length }}"

- name: Informar GMUD ignorada por ativo não encontrado no Zabbix
  ansible.builtin.debug:
    msg: >-
      GMUD {{ gmud.chave }} ignorada no Zabbix: esperados
      {{ gmud.ativos | length }} ativos, encontrados {{ zbx_hosts | length }}
      ({{ zbx_hosts | join(', ') }}). Nenhuma maintenance será criada.
  when: not gmud_valida_zabbix

- name: Mostrar o que será colocado em manutenção no Zabbix
  ansible.builtin.debug:
    msg:
      gmud: "{{ gmud.chave }}"
      nome_maintenance: "GMUD {{ gmud.chave }}"
      inicio: "{{ zbx_inicio }}"
      fim: "{{ zbx_fim }}"
      duracao_minutos: "{{ zbx_minutos }}"
      hosts: "{{ zbx_hosts }}"
  when: gmud_valida_zabbix

- name: Criar maintenance no Zabbix
  community.zabbix.zabbix_maintenance:
    state: present
    name: "GMUD {{ gmud.chave }}"
    desc: >-
      Outage automático para a GMUD {{ gmud.chave }} - {{ gmud.resumo }}
    host_names: "{{ zbx_hosts }}"
    visible_name: "{{ zabbix_usar_visible_name }}"
    collect_data: "{{ zabbix_collect_data }}"
    active_since: "{{ zbx_inicio }}"
    active_till: "{{ zbx_fim }}"
    minutes: "{{ zbx_minutos }}"
  delegate_to: "{{ zabbix_inventory_host }}"
  environment: "{{ proxy_env }}"
  register: zbx_maintenance
  when:
    - gmud_valida_zabbix
    - not zabbix_validate_only

- name: Informar resultado do Zabbix
  ansible.builtin.debug:
    msg:
      gmud: "{{ gmud.chave }}"
      resultado: >-
        {{
          'VALIDAÇÃO OK - nenhuma maintenance foi criada'
          if zabbix_validate_only
          else 'Maintenance criada/atualizada no Zabbix'
        }}
  when: gmud_valida_zabbix
